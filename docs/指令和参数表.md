# 果蝇1号 · DF-01 串口指令和参数表

本文档依据当前固件实现整理。多字节数据均按原始十六进制字节发送，不发送 ASCII 字符串。

## 1. 串口参数

| 项目 | 参数 |
|---|---|
| 接口 | UART TTL |
| 波特率 | 出厂默认 115200 bit/s；固件保留 `2C`，但本项目上位机固定使用 115200，不提供改波特率功能 |
| 数据格式 | 8 数据位、1 停止位、无校验（8N1） |
| 硬件流控 | 无 |
| 模块地址/ID | 出厂默认 `00`，可通过 `2D`修改并保存 |
| 发送帧间隔 | 模块连续发送的两个完整数据包之间至少间隔 5 ms |

## 2. 数据帧格式

未转义的逻辑帧格式如下：

| 字段 | 长度 | 说明 |
|---|---:|---|
| 帧头 | 1 byte | 固定为 `7F`，不参与校验 |
| 长度 | 1 byte | `地址 + 命令 + 参数`的总字节数，即 `3 + 参数长度` |
| 地址 | 1 byte | 必须等于模块当前 ID，否则不响应 |
| 命令 | 1 byte | 请求或响应命令码 |
| 参数 | n bytes | 由具体命令定义，可以为空 |
| 校验 | 1 byte | `长度 XOR 地址 XOR 命令 XOR 全部参数` |

### 2.1 `7F` 转义

除第一个帧头外，从“长度”到“校验”的任意字节如果等于 `7F`，在线路上均发送为 `7F 7F`。接收方校验前需要把重复的 `7F 7F`还原成一个 `7F`。

例如，参数中的一个字节为 `7F`，线路数据应包含：

```text
... 7F 7F ...
```

### 2.2 校验示例

读取卡号请求：

```text
7F 03 00 10 13
```

其中校验值：

```text
03 XOR 00 XOR 10 = 13
```

## 3. 上位机实现范围

### 3.1 一定需要实现

| 功能 | 实现要求 |
|---|---|
| 串口通信 | 固定使用 115200 bit/s、8N1、无流控；支持模块 ID 地址字段 |
| 流式收包 | 在串口字节流中查找帧头 `7F`，按长度收取完整帧，不能假设一次串口回调就是一个完整数据包 |
| 转义和校验 | 发送时对非帧头的 `7F` 做双字节转义；接收时先反转义，再校验长度、地址和 XOR |
| 响应分发 | 支持 `90`、`91`、`92`、`AB`、`AD`、`AE`、`AF`、`B0`、`B1` 响应，并处理 `00/FF/FE/FD/FB` 状态码 |
| 自动读取 | 使用 `2E` 一次设置“自动读卡号”、“关闭自动”或“自动读数据块”，随后被动接收 `90/91` 上报 |
| 手动读取 | 用户单次点击时发送一次 `10` 或 `11`，并等待对应 `90` 或 `91` |
| 写数据块 | 用户确认写入时发送一次 `12`，根据 `92` 状态显示成功、无卡、密钥/权限错误或通信错误 |
| 配置同步 | 连接模块后发送一次 `31`，用 `B1` 刷新界面中的 ID、波特率（只读显示）、自动模式、块号、密钥、防重读时间和增益 |
| 配置修改 | 根据用户操作发送 `2B`、`2D`、`2E`、`2F`、`30`；只有收到成功响应后才更新界面中的已保存值 |

`90` 和 `91` 同时用于指令响应和自动上报。上位机应结合“是否有待完成的手动请求”分发数据；没有待完成请求时收到的 `90/91` 按自动上报处理。

### 3.2 上位机无需实现

| 功能 | 原因/替代方案 |
|---|---|
| 上位机循环发送读卡指令 | 不要用定时器连续发送 `10` 或 `11`；持续读取交给模块 `2E` 自动模式 |
| 改变波特率 | 上位机固定 115200 bit/s，不提供 `2C` 操作入口；`2C/AC` 仅作为固件兼容指令保留 |
| 上位机防重读计时 | 防重读 UID、TIM14 单次定时和 LED2 均由模块端管理；上位机只负责通过 `2F` 设置参数 |
| 主动控制 LED | LED1/LED2 是模块内部状态指示，协议没有 LED 控制指令 |
| RC522 IRQ 功能 | 硬件 IRQ 引脚是保留接口，当前固件未使用，上位机也无需处理 |
| 文本/调试日志解析 | 模块正式通信只发送二进制十六进制帧，错误数据不额外输出调试文本 |
| `A0`、`13`～`16`、`93`～`96` | 当前固件未实现卡密码验证上报、制卡、清卡、充值和扣款，上位机暂不提供相关功能 |

### 3.3 推荐通信流程

1. 以 115200 bit/s、8N1 打开串口。
2. 发送 `31`读取完整配置，用 `B1` 初始化界面。
3. 仅在用户改变工作模式时发送一次 `2E`。
4. 正常运行时不循环发命令，持续解析模块主动发送的 `90/91`。
5. 用户点击手动读取或写入时，只发送一次对应指令并等待响应，不要在上一条请求未完成时重复发送。

## 5. 已实现指令详解

### 5.1 读取卡号 `10`

请求参数为空：

```text
7F 03 00 10 13
```

成功响应参数：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 状态，成功为 `00` |
| 1 | 2 | 卡类型 ATQA |
| 3 | 4 | UID |

示例响应：

```text
7F 0A 00 90 00 04 00 E0 45 AF AB 3F
```

解析结果：状态 `00`，ATQA `04 00`，UID `E0 45 AF AB`。

对于 7 字节或 10 字节 UID，当前协议只上报 UID 的最后 4 字节。手册中的卡号数值按小端方式解释，例如收到 `AA BB CC DD` 时，数值为 `0xDDCCBBAA`。

### 5.2 读取数据块 `11`

请求参数：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 块号/页号 |

读取块 `01` 的请求：

```text
7F 04 00 11 01 14
```

成功响应参数：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 状态，成功为 `00` |
| 1 | 2 | 卡类型 ATQA |
| 3 | 4 | UID |
| 7 | 16 | 数据块内容 |

示例响应：

```text
7F 1A 00 91 00 04 00 E0 45 AF AB D3 C5 C1 E9 BF C6 BC BC 00 00 00 00 00 00 00 00 69
```

当前读取规则：

- MIFARE Classic 类卡片使用 Key A 验证，当前默认密钥为 `FF FF FF FF FF FF`。
- MIFARE Ultralight/NTAG 不进行 Crypto1 验证，一次读取连续 4 页，共返回 16 字节。
- 显式发送 `11` 指令时不受自动上报防重读规则限制。

### 5.3 写数据块 `12`

请求参数共 17 字节：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | MIFARE Classic 块号 |
| 1 | 16 | 要写入的数据 |

响应参数为“状态(1) + ATQA(2) + UID(4)”，命令码为 `92`。固件先使用 Key A 执行完整的“认证 + 写命令 ACK + 16 字节数据 ACK”流程。Key A 路径任何一步失败时，会退出 Crypto1、重新唤醒并选中同一张卡，再使用 Key B 从认证开始完整重试。这样可支持“Key A 可读、Key B 才有写权限”的扇区访问位配置。

写块状态码：

| 状态 | 含义 |
|---:|---|
| `00` | 写入两阶段均收到 ACK |
| `FF` | 未检测到卡 |
| `FD` | Key A/Key B 认证失败，或卡片对写命令/数据阶段返回 NACK（密钥或访问权限不匹配） |
| `FE` | 选卡失败、通信超时或 ACK 帧格式错误 |

> 写入块 0 或扇区尾块可能破坏 UID、密钥及访问控制位。固件不会擅自修改用户指定的块号，调用方必须自行确认目标块可安全写入。`12`当前不支持 Ultralight/NTAG 的 4 字节页写入。

手册中的写块示例：

```text
7F 14 00 12 01 D3 C5 C1 E9 BF C6 BC BC 00 00 00 00 00 00 00 00 40
```

例如写入成功且卡片 `ATQA=04 00`、`UID=2A E6 94 AC`，响应为：

```text
7F 0A 00 92 00 04 00 2A E6 94 AC 68
```

> 命令中的块号是单字节十六进制值。例如 `18` 表示块 `0x18`（十进制 24），不是十进制 18。

### 5.4 装载密钥 `2B`

请求参数共 18 字节：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 6 | Key A |
| 6 | 6 | Key B |
| 12 | 6 | 固定确认码 `00 03 08 05 02 07` |

设置成功后返回 `AB`和状态 `00`。Key A、Key B 会立即生效并保存到 Flash；读取 MIFARE Classic 数据块时先尝试 Key A，失败后再尝试 Key B。出厂默认 Key A 和 Key B 均为 `FF FF FF FF FF FF`。

### 5.5 设置波特率 `2C`

> 本命令仅作为固件兼容能力保留。本项目上位机固定使用 115200 bit/s，不需要实现以下设置界面或发送逻辑。

请求参数共 7 字节：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 4 | 波特率整数，兼容低字节在前和高字节在前 |
| 4 | 3 | 固定确认码 `98 24 31` |

支持的波特率：`2400`、`4800`、`9600`、`14400`、`19200`、`28800`、`38400`、`57600`、`115200`。

设置响应 `AC`使用旧波特率发送。响应发送完成并经过 5 ms 帧间隔后，模块切换到新波特率；新值同时写入 Flash，重新上电后继续使用。

以低字节在前的 115200（`00 C2 01 00`）为例，模块 ID 为 `00`时：

```text
7F 0A 00 2C 00 C2 01 00 98 24 31 68
```

### 5.6 设置模块 ID `2D`

请求参数为“新 ID + 固定确认码”：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 新模块 ID，范围 `00`～`FF` |
| 1 | 3 | 固定确认码 `37 21 56` |

模块只处理地址字段等于当前 ID 的帧。ID 设置成功后立即生效并写入 Flash，`AD`成功响应使用新 ID。

当前 ID 为 `00`，设置新 ID 为 `01`：

```text
发送：7F 07 00 2D 01 37 21 56 6B
接收：7F 04 01 AD 00 A8
```

后续发给该模块的命令需要把地址改为 `01`并重新计算 XOR 校验。

### 5.7 设置自动方式 `2E`

请求必须包含 10 字节参数：

| 偏移 | 长度 | 名称 | 取值/说明 |
|---:|---:|---|---|
| 0 | 1 | 模式 | `00`自动读卡号；`01`关闭自动读取；`02`自动读数据块 |
| 1 | 1 | 模式校验 | 必须等于`模式 + 0A` |
| 2 | 1 | 块号 | 自动读数据块时使用；其他模式忽略 |
| 3 | 4 | 初始值 | 手册保留字段，当前固件接收但不使用 |
| 7 | 3 | 固定确认码 | 必须为 `23 12 54` |

有效参数设置成功后响应：

```text
7F 04 00 AE 00 AA
```

常用设置示例：

| 功能 | 完整指令 |
|---|---|
| 自动读卡号 | `7F 0D 00 2E 00 0A 01 00 00 00 01 23 12 54 4C` |
| 关闭自动读取 | `7F 0D 00 2E 01 0B 01 00 00 00 01 23 12 54 4C` |
| 自动读取数据块 1 | `7F 0D 00 2E 02 0C 01 00 00 00 01 23 12 54 48` |

自动上报规则：

- 模式 `00`检测到新 UID 后主动发送 `90`。
- 模式 `02`读取设置的块号后主动发送 `91`。
- 同一 UID 成功自动上报后，在防重读记录被清除前不会重复上报。
- 防重读时长为 `100`～`3000` ms 时，LED2 点亮并启动 TIM14 单次定时。TIM14 不开启更新中断；主循环轮询 UIF 到期标志后灭灯、清除已记录 UID，并确保定时器关停。卡片如果仍在感应区，会在后续轮询中再次上报。
- 防重读时长为 `0` 时，同一 UID 无限期禁止重复上报；LED2 仅点亮 500 ms。主循环检测到 TIM14 单次到期后只灭灯并关停定时器，不清除 UID、不产生上报、不闪烁。
- 防重读期间检测到不同 UID 时可以立即上报，并以新 UID 替换当前防重读记录。
- 每次成功执行 `2E`设置自动方式指令时都会清除防重读记录；即使模式值未改变，当前卡也可在下一次轮询重新上报。
- 主机主动发送读取卡号 `10` 或读取数据块 `11` 指令时不受上述防重读规则限制。手动读取成功后，如果该 UID 与当前防重读 UID 相同，固件会立即清除防重读状态、熄灭 LED2 并关停 TIM14；UID 不同或读取失败时不改变原状态。
- 自动模式中的寻卡、选卡、认证或读取错误不会主动上报。

TIM14 的更新中断始终关闭，到期处理在主循环下一次轮询时执行，因此实际处理时刻可能比设置值略晚。

自动模式、块号和初始值字段均保存到 Flash，重新上电后恢复。

### 5.8 设置防重读 RESET 时长 `2F`

这是当前固件增加的扩展指令，参数为 2 字节无符号毫秒值，低字节在前。有效值为 `0` 或 `100`～`3000` ms，出厂默认为 `0`（同 UID 无限防重读）；`1`～`99` 和大于 `3000` 的值会返回参数错误。设置成功后立即清除当前防重读 UID，并将新值写入 Flash，下次开机自动读取。

`0` 表示同一 UID 无限期禁止重复上报，不表示循环定时。每次有效上报后 LED2 仅由 TIM14 单次定时 500 ms 后熄灭，主循环轮询到 UIF 标志后关停定时器，不执行其他操作。

设置为 1000 ms（`03E8`，低字节在前为 `E8 03`），模块 ID 为 `00`时：

```text
发送：7F 05 00 2F E8 03 C1
接收：7F 04 00 AF 00 AB
```

设置为 `0`（同一 UID 无限防重读，LED2 单次点亮 500 ms）：

```text
发送：7F 05 00 2F 00 00 2A
接收：7F 04 00 AF 00 AB
```

### 5.9 设置天线接收增益 `30`

请求参数为 1 字节增益档位，直接对应 MFRC522 `RFCfgReg.RxGain[2:0]`：

| 档位 | 标称增益 |
|---:|---:|
| `00` | 18 dB（最低） |
| `01` | 23 dB |
| `02` | 18 dB（重复档） |
| `03` | 23 dB（重复档） |
| `04` | 33 dB（默认） |
| `05` | 38 dB |
| `06` | 43 dB |
| `07` | 48 dB（最高） |

设置成功后立即更新 RC522 寄存器并写入 Flash。`B0` 响应返回“状态 + 寄存器实际档位”。设置最高档 `07`：

```text
发送：7F 04 00 30 07 33
接收：7F 05 00 B0 00 07 B2
```

### 5.10 读取全部配置 `31`

请求不带参数：

```text
发送：7F 03 00 31 32
```

`B1` 响应参数共 27 字节：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 状态，`00`成功 |
| 1 | 1 | 模块 ID |
| 2 | 4 | 波特率，低字节在前 |
| 6 | 1 | 自动工作模式 |
| 7 | 1 | 自动读取块号 |
| 8 | 4 | 自动方式初始值 |
| 12 | 6 | Key A |
| 18 | 6 | Key B |
| 24 | 2 | 防重读 RESET 毫秒值，低字节在前 |
| 26 | 1 | 天线增益档位 |

出厂默认配置、模块 ID 为 `00` 时的响应：

```text
7F 1E 00 B1 00 00 00 C2 01 00 00 01 00 00 00 01 FF FF FF FF FF FF FF FF FF FF FF FF 00 00 04 68
```

> `B1` 会返回 Key A 和 Key B，上位机应按敏感配置数据处理。

## 6. Flash 参数保存

固件在 PY32F002B 的最后一个 128 字节 Flash 页保存配置，地址范围为 `0x08005F80`～`0x08005FFF`；链接脚本已经将该页从程序空间中排除。

| 持久化参数 | 出厂默认值 |
|---|---|
| 模块 ID | `00` |
| 波特率 | 115200 |
| 自动模式 | `00`，自动读卡号 |
| 自动读取块号 | `01` |
| 自动方式初始值 | `00 00 00 01` |
| Key A | `FF FF FF FF FF FF` |
| Key B | `FF FF FF FF FF FF` |
| 防重读 RESET 时长 | `0`，同 UID 无限防重读 |
| 天线接收增益 | `04`，33 dB |

配置页包含格式版本和 CRC32。开机时校验成功才加载；空白、版本错误或 CRC 错误时恢复出厂默认值并重新保存。升级到 Flash 配置格式 v5 时，旧版页面的防重读时间会一次性改为 `0`，其他有效参数保留；之后用户通过 `2F` 设置的值会正常保存。重复设置为完全相同的参数时不重复擦写 Flash，以减少擦写损耗。

## 7. 状态码

| 状态码 | 含义 | 当前使用情况 |
|---:|---|---|
| `00` | 成功 | 已使用 |
| `FF` | 无卡 | 读取卡号、读取数据块指令使用 |
| `FE` | 读写错误或无卡 | 当前用于选卡、认证、读取失败及自动方式参数错误 |
| `FD` | 密码或访问权限错误 | 写块认证失败或卡片返回 MIFARE NACK 时使用 |
| `FC` | 余额不足 | 手册定义，当前未实现 |
| `FB` | 校验错误 | 当前用于卡片数据块 CRC 错误；串口帧校验错误则直接丢弃、不响应 |

## 8. 常见 ATQA 卡类型

| ATQA | 类型 |
|---|---|
| `04 00` | MIFARE Classic 1K / S50（常见配置） |
| `44 00` | MIFARE Ultralight（手册定义） |

ATQA 只能用于初步识别，不应作为完整的卡片型号判断依据；部分兼容卡、CPU 卡或复合卡可能返回其他值。

## 9. 当前固件的异常处理

- 帧头错误、长度错误、地址与当前模块 ID 不同或 XOR 校验错误：丢弃该帧，不发送错误响应。
- `10`或`11`的参数长度不正确：当前不发送响应。
- `2E`参数长度、模式校验或固定确认码错误：返回 `AE`，状态为 `FE`。
- 制卡、清卡、充值和扣款命令目前仅保留空函数，不发送响应。
